# 安全與公開發布

## 機密資料

禁止將 API key、token、密碼、cookie、私鑰、`.env`、服務帳號憑證、客戶資料、個人識別資訊或未脫敏日誌寫入規則、Skill、交接或 Git。

## 公開倉庫檢查

公開發布前：

1. 確認倉庫可見性與預期受眾。
2. 只選擇可公開且可維護的規則與自建技能；排除平台/第三方原始碼、商業機密、專案快照及私有設定。
3. 以通用名稱替換人名、公司/供應商、主機路徑、內部 Port、網址、帳號與業務專屬欄位。
4. 檢查忽略檔、`git status`、完整 diff 與敏感資料掃描結果。
5. 推送後檢查遠端檔案清單與提交內容；若發現秘密，先撤銷/輪替憑證，再依 GitHub 機密事件流程處理，不能只刪最新檔案。

不要因為文件不是程式碼，就假設它不含敏感資訊。
