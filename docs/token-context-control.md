# Token 與 Context 控制

目標是降低不必要的讀取、重複推理與輸出，而不是犧牲正確性或測試。

## 讀取策略

1. 先讀入口規則與任務直接相關的唯一來源。
2. 用精確搜尋定位命中，再讀必要片段；排除依賴目錄、生成物、備份、快取與大型日誌。
3. 只有遇到實際缺口才擴大搜尋範圍；已驗證且仍新鮮的證據可重用。
4. 先用一位主責完成一般任務；只為具體風險或證據缺口增加另一個工具。

## 壓縮與交接

- 以介面或工具提供的實際 context 指標為準；未知時不猜百分比、不混用帳號訂閱額度。
- Context 變少時，先保留目標、決策、目前狀態、檔案差異、測試、風險與下一步。
- 摘要只追加新決策與狀態，不重寫已共享內容，不貼完整對話歷史。
- 長輸出存入任務文件並在回覆中提供摘要、路徑與必要證據。

## 回覆策略

- 先給結果，再列實際驗證與尚未解決的風險。
- 避免空白模板、重複解釋及只為形式而召集多工具。
- 不以短輸出掩蓋錯誤、不確定性或未執行的測試。
