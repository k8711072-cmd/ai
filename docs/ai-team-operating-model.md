# AI 團隊運作模型

## 原則

1. **單一共用分工來源**：角色、派工及交接格式集中在本文件；工具專屬檔只描述自身邊界。
2. **動態主責**：每個任務按能力、風險、可用性、成本及上下文選一位主責，不指定永久指揮工具。
3. **最少足夠協作**：一般任務不啟動全隊；額外審查者必須補足明確的證據或專業缺口。
4. **狀態與產出分離**：若專案使用 Runner，Runner 是該專案唯一狀態權威；沒有 Runner 時，以明確的任務紀錄作為狀態來源，不假稱背景工作正在執行。
5. **品質不隨成本降級**：可按任務切換模型檔或工具，但不可省略安全界線、測試或資料驗證。

## 任務級別與協作

| 級別 | 適用情境 | 協作方式 |
|---|---|---|
| `L0` | 問答、唯讀查詢 | 當前工具直接回覆，不外派 |
| `L1` | 小型、低風險、單一範圍修改 | 一位主責；最小測試 |
| `L2` | 多步驟但邊界清楚的工作 | 一位主責；必要時一次定點複核 |
| `L3` | 架構、安全、正式資料或高影響決策 | 兩位獨立審查者、一次交叉挑戰、可否證測試；再由一位主責執行 |
| `L4` | 新工具、新流程或實驗性整合 | 隔離、合成/脫敏資料、明確回滾方式 |

L3 審查需回答：最大失敗模式、未證實假設、最強反對理由、最快反證測試、採納/拒絕理由及驗證負責人。共識本身不是證據；無法消除的風險要明確列出。

## 模型與能力

- 使用 `low | standard | high` 這類抽象成本層級；精確模型由當前產品、帳號、權限及成功呼叫確認。
- 簡單任務不例行探測昂貴模型。只在標準路徑不足且有具體新證據時升級。
- 模型或權限錯誤後停止重複嘗試，記錄降級原因並改用已驗證路徑。
- 請求最高模型只代表在可用能力內挑選合適候選，不代表購買額度、改全域設定或跳過安全限制。

## 派工與交接

派工最少包含：任務與目標、唯一主責、級別、範圍、不可動項、資料風險、驗收方式與證據位置。

交接最少包含：目標、主責、已完成差異、修改檔案、驗證命令/結果、未解風險、阻礙與下一步。只傳必要上下文，不複製完整聊天歷史。

## 持續推進

- 對可逆、範圍清楚的工作直接執行並驗證，不在每個小步驟停下詢問。
- 同一解法在同一位置因同一原因失敗兩次後，停止重試；換方法、補證據或縮小分支，其他可獨立工作照常推進。
- 外部登入、付費、法律承諾、不可逆正式操作或無安全替代的重大決策，僅隔離受阻部分並清楚說明所需本人動作。
- 不把背景進程、跨重啟持續性或跨工具交接描述成已完成，除非有狀態紀錄可驗證。
